# Protocol: how much data description should the system prompt carry?

Written 2026-10-15, before any run. Archived copy and results: experiments/2026-10-15-prompt-variants/ (the experiment folder).

## Research question
Does the amount and kind of data description in the system prompt change the correctness or latency of answers from gpt-oss-20b on 2024 F1 data?

## Variants (the only thing that changes between arms)
The text that replaces the data guide in the system prompt. Files are in eval/variants/.
- V0 baseline: no data guide (v0.txt is empty). Schema block and rules only.
- V1 shorthand (v1.txt): one line per table, column names with one-line meanings, units in two lines.
- V2 medium (v2.txt): grain, units, derived columns, the common-question recipes, one short line per column.
- V3 detailed (v3.txt): the current web/src/dataGuide.ts, unchanged. v3.txt is generated by eval/variants/make_v3.mjs and the runner refuses to start if it differs from the source.
Identical in all four: the intro line, the schema block (generated from DuckDB, with 3 sample rows per table), the existing rules, the tool definition, and the new rule below.

## Rule added to RULES in every variant (eval/variants/rule.txt)
- The rows returned by run_sql (at most 50 rows, plus row_count, the number of rows the query produced) are sent back to you as the tool result. Read them and use them directly in your answer, quoting values exactly. If row_count is above 50 only the first 50 rows are shown, so aggregate or filter in SQL instead.

Row limit: 50, the number the app already sends back and states in the run_sql description, so nothing else had to change.

## Questions (eval/questions.json, id: text)
- wins_team: Which team won the most races in 2024, and how many? (Red Bull Racing, 9)
- top_compound: Which tyre compound was used for the most race laps in 2024? (HARD, 13767)
- bahrain_clean_pace: In the 2024 Bahrain Grand Prix, who had the faster race pace, Verstappen or Norris? Use only green-flag laps, excluding in-laps, out-laps and deleted laps. Give the median lap time for each.
- unanswerable: Who won the 2023 Monaco Grand Prix? (must decline and name no driver)

Ground truth comes from Python DuckDB over the raw Parquet (eval/ground_truth.py), not the app views. Green-flag lap definition for bahrain_clean_pace: laps rows with session R, race bahrain_grand_prix, Driver VER or NOR, TrackStatus exactly '1' (no other status code at any time in the lap), LapTime not null, PitInTime null (not an in-lap), PitOutTime null (not an out-lap), Deleted not true. Median of an even count is the mean of the two middle laps. Result: VER 95.477 s (49 laps), NOR 96.5365 s (48 laps), so Verstappen is faster by 1.0595 s. The file is frozen by the SHA-256 in eval/experiment/questions.sha256; the runner refuses to start if it changes. Expected values are not changed after the first run.

## Hypotheses
- H1: V2 matches V3 accuracy at lower latency and fewer prompt tokens.
- H2: V0 is clearly worse than V1 in accuracy (the lap-level and compound questions need column meanings).
- H3: V1 is between V0 and V2 on accuracy.
- H4: Longer prompts cost more latency: median latency rises from V0 to V3.
- Null: no accuracy difference between any pair.
What counts as a difference: with 5 repeats per cell and 20 runs per variant, a gap of 3 or more passes out of 5 in a single question cell, or 6 or more passes out of 20 for a variant overall, is reported as a suggestive difference. Anything smaller is reported as no detectable difference. Latency: a difference in the median of more than 20 percent that has the same sign in at least 3 of the 4 questions. These are descriptive thresholds, not significance tests; single runs are never reported as results.

## Design
4 variants x 4 questions x 5 repeats = 80 runs. Order: for each repeat, the 16 variant-question cells are shuffled with a seeded PRNG (mulberry32, seed 20261015, in eval/run_experiment.mjs). Variants are therefore interleaved, and a run stopped early still has a balanced number of repeats. Every run imports a fresh copy of the app module (empty history, schema regenerated) and a new DuckDB instance with new views. Nothing carries over.
Logging: eval/experiment/runs.jsonl, one JSON line per run (hashes of variant file, rule, schema block, final system prompt; every request and response; usage tokens; per-call and total latency; every SQL with row count and error flag; answer; strict verdict and parsed values). Summary: eval/experiment/summary.md.

## Pilot
One run first (V3, bahrain_clean_pace) to check logging, usage fields, and whether temperature and reasoning are accepted. Logged to eval/experiment/pilot.jsonl, not counted in the grid. If wrong, stop and report.

## Stop conditions
Quota error (4006 or similar): stop, keep logs, no retry. More than 5 consecutive infrastructure errors: stop. Rough budget: the free allowance is 10,000 neurons a day; a V3 run with 2 to 3 model calls on a prompt of several thousand tokens may use a few hundred neurons, so the full grid may not fit in one day. The pilot gives the real figure.
